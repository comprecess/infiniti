# Руководство по валидации MVP: Кейс Finandy

Данный документ предназначен для проведения реального тестирования MVP программы Growth & Exit на примере компании Finandy. Руководство описывает пошаговые сценарии для всех участников процесса, ожидаемые результаты и ключевые вопросы для сбора обратной связи.

---

## 1. Подготовка к тестированию (Deal Manager)

Перед началом тестирования с реальным клиентом, Deal Manager должен подготовить окружение.

**Действия:**
1. Авторизоваться в панели администратора (`https://console.infiniti.stream`).
2. Создать новый проект с шаблоном `exit_deal` и названием "Finandy Exit Preparation".
3. Сгенерировать ссылку-приглашение для Founder (Основателя Finandy) через API участников проекта.
4. Отправить ссылку Основателю для начала процесса онбординга.

**Ожидаемый результат:**
Проект успешно создан в базе данных, структура папок Deal Room инициализирована, ссылка для входа Founder сгенерирована и активна.

---

## 2. Сценарий 1: Онбординг и сбор данных (Founder)

**Роль:** Основатель Finandy (Founder)
**Цель:** Пройти первичный сбор данных и оценить удобство процесса.

**Шаги:**
1. Перейти по предоставленной ссылке-приглашению (автоматический вход в систему).
2. Заполнить базовую информацию о компании (Название: Finandy, Индустрия: Fintech/Crypto, количество сотрудников).
3. Ввести финансовые показатели (Текущий MRR, темпы роста, отток клиентов).
4. Завершить процесс онбординга.
5. Перейти в раздел Deal Room и ознакомиться с автоматически созданной структурой папок.

**Ожидаемый результат:**
Данные успешно сохранены в `shared_preferences` проекта. Founder видит структуру папок (Financial, Legal, Operational и т.д.) и понимает, куда необходимо загружать документы.

**Вопросы для обратной связи (Задать Основателю):**
* Насколько понятны вопросы в процессе онбординга?
* Хватает ли предложенных папок в Deal Room для структурирования ваших документов?
* Какие метрики вы бы хотели добавить на этапе сбора данных?

## 3. Сценарий 2: Оценка и План роста (Deal Manager & Founder)

**Роль:** Deal Manager и Основатель Finandy
**Цель:** Зафиксировать базовую оценку стоимости и сформировать план по ее увеличению.

**Шаги Deal Manager:**
1. Проанализировать введенные финансовые данные Finandy.
2. В панели управления создать текущую оценку (Current Valuation), указав базовую метрику (например, Annual Revenue) и мультипликатор для Fintech отрасли.
3. Сформировать 2-3 инициативы (Growth Items) для увеличения стоимости. Пример:
   * *Инициатива 1:* "Получение лицензии VASP" (Категория: Compliance, Стоимость: $50k, Влияние на мультипликатор: +1.5x).
   * *Инициатива 2:* "Запуск B2B направления" (Категория: Commercial, Стоимость: $30k, Влияние на выручку: +$500k).
4. Убедиться, что система рассчитала Projected Value и Best Case Value.

**Шаги Founder:**
1. Зайти в портал и открыть раздел Valuation.
2. Ознакомиться с текущей оценкой и потенциалом роста.
3. Перейти в раздел Growth Plan и изучить предложенные инициативы.
4. Нажать кнопку "Approve" (Одобрить) для инициативы "Получение лицензии VASP".

**Ожидаемый результат:**
Deal Manager успешно создает оценку и план. Founder видит четкую разницу между текущей и потенциальной стоимостью. При одобрении инициативы система автоматически меняет ее статус на `approved`, создает задачу (Task) в системе, генерирует коммерческое предложение (Offer) и счет (Invoice).

**Вопросы для обратной связи:**
* Понятна ли логика расчета потенциальной стоимости (Projected Value)?
* Достаточно ли информации в карточке Growth Item для принятия решения об инвестировании в эту инициативу?
* Удобен ли процесс одобрения инициативы и автоматического формирования счета?

## 4. Сценарий 3: Due Diligence (Investor & Buyer)

**Роль:** Потенциальный Инвестор и Покупатель
**Цель:** Проверить ролевую модель доступа и удобство представления данных для внешних сторон.

**Шаги Deal Manager:**
1. Через API участников пригласить Инвестора (роль `investor`) и Покупателя (роль `buyer`).
2. Предоставить им соответствующие ссылки для входа.

**Шаги Investor:**
1. Авторизоваться по ссылке.
2. Проверить доступность разделов: должен видеть Deal Room (только чтение), Valuation (только сводная информация, без деталей расчета), Growth Plan (только чтение).
3. Попытаться зайти в раздел Onboarding (доступ должен быть закрыт).

**Шаги Buyer:**
1. Авторизоваться по ссылке.
2. Проверить доступность разделов: должен видеть Deal Room (только чтение) и Valuation (только сводная информация).
3. Убедиться, что разделы Growth Plan и Onboarding недоступны.

**Ожидаемый результат:**
Система строго соблюдает права доступа (`ProjectParticipantAccess` middleware). Инвестор видит план роста компании, а покупатель оценивает только текущее состояние и документы.

**Вопросы для обратной связи:**
* Хватает ли Инвестору предоставленной информации для принятия решения?
* Удобно ли Покупателю ориентироваться в Deal Room?
* Какие дополнительные отчеты или выгрузки хотелось бы видеть в этих ролях?

После прохождения всех сценариев необходимо:

2. Собрать ответы на вопросы для обратной связи.
3. Провести интервью с Founder Finandy для получения общих впечатлений о ценности продукта.
4. На основе полученных данных скорректировать приоритеты для Фазы 6.
